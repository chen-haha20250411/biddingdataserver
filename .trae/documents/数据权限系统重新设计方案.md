# 数据权限系统重新设计方案

## 一、数据库表设计

### 1. 修改现有用户表（operator）

添加部门ID和分支机构ID字段：

```sql
ALTER TABLE operator ADD COLUMN dept_id INT(11) COMMENT '部门ID';
ALTER TABLE operator ADD COLUMN sug_org_id INT(11) COMMENT '分支机构ID';
```

### 2. 创建数据角色表（data\_role）

```sql
CREATE TABLE data_role (
  id INT(11) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  role_name VARCHAR(100) NOT NULL COMMENT '角色名称',
  role_code VARCHAR(50) NOT NULL COMMENT '角色编码',
  description VARCHAR(500) COMMENT '角色描述',
  status TINYINT(1) DEFAULT 1 COMMENT '状态：1-启用，0-禁用',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id),
  UNIQUE KEY uk_role_code (role_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='数据角色表';
```

### 3. 创建数据权限表（data\_permission）

```sql
CREATE TABLE data_permission (
  id INT(11) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  role_id INT(11) NOT NULL COMMENT '数据角色ID',
  permission_type VARCHAR(50) NOT NULL COMMENT '权限类型：CUSTOMER-客户，INDUSTRY-行业，PRODUCT_TYPE-产品类型，PRODUCT_LINE-产品线，WAREHOUSE-仓库，BRANCH-分支机构，DEPARTMENT-部门，EMPLOYEE-员工',
  permission_value VARCHAR(500) NOT NULL COMMENT '权限值（支持多个值，用逗号分隔）',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (id),
  INDEX idx_role_id (role_id),
  INDEX idx_permission_type (permission_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='数据权限表';
```

### 4. 创建用户数据角色关联表（user\_data\_role）

```sql
CREATE TABLE user_data_role (
  id INT(11) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  user_id INT(11) NOT NULL COMMENT '用户ID',
  role_id INT(11) NOT NULL COMMENT '数据角色ID',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (id),
  UNIQUE KEY uk_user_role (user_id, role_id),
  INDEX idx_user_id (user_id),
  INDEX idx_role_id (role_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户数据角色关联表';
```

### 5. 创建部门信息表（department\_info）

```sql
CREATE TABLE department_info (
  id INT(11) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  dept_name VARCHAR(100) NOT NULL COMMENT '部门名称',
  dept_code VARCHAR(50) COMMENT '部门编码',
  parent_id INT(11) DEFAULT 0 COMMENT '父级部门ID',
  dept_level INT(2) DEFAULT 1 COMMENT '部门层级',
  status TINYINT(1) DEFAULT 1 COMMENT '状态：1-启用，0-禁用',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id),
  INDEX idx_parent_id (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='部门信息表';
```

### 6. 创建分支机构信息表（branch\_info）

```sql
CREATE TABLE branch_info (
  id INT(11) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  branch_name VARCHAR(100) NOT NULL COMMENT '分支机构名称',
  branch_code VARCHAR(50) COMMENT '分支机构编码',
  parent_id INT(11) DEFAULT 0 COMMENT '父级机构ID',
  branch_level INT(2) DEFAULT 1 COMMENT '机构层级',
  status TINYINT(1) DEFAULT 1 COMMENT '状态：1-启用，0-禁用',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id),
  INDEX idx_parent_id (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='分支机构信息表';
```

## 三、核心功能实现

### 1. 数据角色管理

* 创建数据角色

* 查询数据角色列表

* 更新数据角色信息

* 删除数据角色

### 2. 数据权限管理

* 为数据角色分配权限（支持多颗粒度）

* 查询数据角色的权限列表

* 更新数据权限

* 删除数据权限

### 3. 用户数据角色分配

* 为用户分配数据角色

* 查询用户的数据角色列表

* 撤销用户的数据角色

* 批量分配/撤销数据角色

### 4. 权限检查逻辑

* 根据用户ID查询用户的数据角色

* 根据数据角色查询对应的权限

* 支持多颗粒度权限检查（客户、行业、产品类型、产品线、仓库、分支机构、部门、员工）

* 权限缓存机制（使用Redis）

## 四、API接口设计

### 1. 数据角色管理API

* POST /api/dataRole/create - 创建数据角色

* GET /api/dataRole/list - 查询数据角色列表

* PUT /api/dataRole/update - 更新数据角色

* DELETE /api/dataRole/delete/{id} - 删除数据角色

### 2. 数据权限管理API

* POST /api/dataPermission/assign - 为数据角色分配权限

* GET /api/dataPermission/list/{roleId} - 查询数据角色的权限列表

* PUT /api/dataPermission/update - 更新数据权限

* DELETE /api/dataPermission/delete/{id} - 删除数据权限

### 3. 用户数据角色分配API

* POST /api/userDataRole/assign - 为用户分配数据角色

* GET /api/userDataRole/list/{userId} - 查询用户的数据角色列表

* DELETE /api/userDataRole/revoke - 撤销用户的数据角色

* POST /api/userDataRole/batchAssign - 批量分配数据角色

### 4. 部门信息管理API

* POST /api/departmentInfo/create - 创建部门

* GET /api/departmentInfo/list - 查询部门列表

* PUT /api/departmentInfo/update - 更新部门信息

* DELETE /api/departmentInfo/delete/{id} - 删除部门

### 5. 分支机构信息管理API

* POST /api/branchInfo/create - 创建分支机构

* GET /api/branchInfo/list - 查询分支机构列表

* PUT /api/branchInfo/update - 更新分支机构信息

* DELETE /api/branchInfo/delete/{id} - 删除分支机构

## 六、技术亮点

1. **多颗粒度权限控制**：支持客户、行业、产品类型、产品线、仓库、分支机构、部门、员工等多个维度的权限控制
2. **角色继承机制**：支持数据角色的继承关系，简化权限管理
3. **权限缓存**：使用Redis缓存权限数据，提高性能
4. **批量操作**：支持批量分配和撤销权限
5. **权限审计**：记录权限操作日志，便于审计
6. **向后兼容**：保持与现有系统的兼容性
